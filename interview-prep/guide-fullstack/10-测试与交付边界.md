# C10 怎样证明项目能工作：测试、配置与交付边界

> 返回：[主导学](../GenBI/导学.md)；前置：[C01](01-项目运行与分层.md)、[C02](02-会话与接口契约.md)、[C05](05-消费幂等与取消.md)；下一步：[面经](../GenBI/面经.md)。  
> 对应：简介；[Q8 验证与交付](../GenBI/面经.md#q8-验证与交付)；目标掌握：看懂链路、理解机制、设计与表达。

## 本课重点

工程能力要说清“验证了什么，以及证据支持到哪里”。当前有后端纯逻辑/fake/HTTP 测试、前端检查与构建工作流、开发依赖 Compose；它们分别保护一部分行为，不能合并成“完整链路已通过生产验收”。

本次课程以实际源码与配置为准。测试通过也不能抵消 C02 的接口差异、C05 的状态机限制与 C06 的通知窗口。

## 主链与职责

```text
后端测试 → 纯逻辑分类 / fake relay / httptest模型超时
前端 CI → 冻结安装 → lint → 格式 → 类型 → Jest → build → 上传dist
本地环境 → Compose中间件 → SQL首次初始化 → HTTP + consumer + 前端
运行证据 → 日志/状态/错误信息；没有现成全链路追踪或性能报告
```

测试层次按替代了什么依赖来判断：fake 存储没有验证 MySQL 事务；HTTP mock 没有调用真实 DeepSeek；纯 CAS 分类没有制造真实并发。

2. [chart_service_cas_test](../../backend/internal/service/chart_service_cas_test.go)：验证 DB 错误、0 行、1 行的结果分类与哨兵识别；没有执行数据库 UPDATE。
3. [deepseek_service_test](../../backend/internal/service/deepseek_service_test.go)：httptest 慢服务、短 Context、取消及 nil Context 兜底。
4. [util 测试](../../backend/internal/util/excel_test.go)、[清洗测试](../../backend/internal/util/echarts_test.go)：CSV 转义与 JSON 清洗；没有浏览器 ECharts 交互。
5. [frontend-ci](../../.github/workflows/frontend-ci.yml)：Node 20、pnpm 按 packageManager、冻结锁文件；Jest passWithNoTests 只允许空测试集，不掩盖真正失败；build 依赖检查成功，上传产物而非部署上线。

## 机制与边界

本次在 2026-11-08、源码基线 `6a0384cbf3a1f1901d5f7e5401fc5905d7590a49` 下执行现有 `go test ./...`，环境 Go 1.27.1 / macOS arm64，退出码 0。outbox、service、util 的现有测试通过；其他多处包显示 no test files。这个结果证明当前测试集通过，不证明消息链路集成、数据库事务或并发恢复无缺陷。

前端仓库没有人工维护的业务测试文件；`.umi-test` 是生成文件，不当作业务测试成果。前端类型检查与专题浏览器验收的实际结果记录在[导学](../GenBI/导学.md)的验证状态中，只有执行完成后才记通过。

Compose 健康检查只说明单个服务响应检查；MySQL 挂载初始化 SQL 只在空数据卷首次执行，修改脚本不会自动迁移已有数据库。持久化卷与应用版本是不同对象，不能用清空数据替代正常迁移。

应用启动配置包含数据库、Redis、MQ、模型 key、任务超时、relay 开关与间隔。配置时长允许纯数字秒或 ParseDuration，缺少正值校验；修改 relay 开关可能让已受理任务积压。当前没有生产网关、发布回滚、数据库迁移框架、后端 CI、端到端契约测试或压测指标。

日志能按 chartId/outboxId 关联部分路径，但没有统一 Trace ID、队列年龄指标和 SLO。故障判断应区分 wait 与 pending、running 与执行租约、数据库终态与页面展示；不能只看 health 或“Redis 可连”认定一切正常。

## 需要懂什么

单元测试擅长检查局部规则；集成测试检查真实依赖的语义；端到端检查两端契约与完整用户流程。一个层面的通过不能自动推广到其他层面。优先验证最可能违背核心承诺的路径，例如 running 后失败重试、订阅前完成、异步返回类型，而非增加镜像实现的测试数量。

如果以后补验证，数据库事务回滚、重复投递、执行者崩溃恢复、SSE 初始状态与前后端错误契约应优先；这些是建议的验证范围，当前没有声称执行过。没有压测，简历使用具体机制效果，不写吞吐、延迟提升或“高并发零丢失”。

部署边界要包含静态站点代理、Cookie/TLS、SSE 缓冲与超时，以及两个 Go 进程的存活、重连和停机。环境能拉起不等于生产交付已经完整。

## 需要记住什么

- fake relay 验规则，CAS 测试只验分类，httptest 验 HTTP Context；现有 Go 测试通过有明确环境。
- 前端 CI 有检查与构建，Jest 可为空；上传 dist 不是部署。
- 初始化 SQL 只针对首次空卷；health 不是整条任务链 readiness。
- 用[Q8](../GenBI/面经.md#q8-验证与交付)说明已证实能力、验证层次和下一步，不补造线上数字。
