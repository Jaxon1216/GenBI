# C02 登录后访问图表：会话、权限与接口契约

> 课程性质：核心  
> 返回：[主导学](../GenBI/导学.md)；前置：[C01 运行入口](01-项目运行与分层.md)；下一课：[C03 上传](03-上传与同步生成.md)。  
> 对应：简介；[Q7 会话与权限](../GenBI/面经.md#q7-会话与权限)；目标掌握：看懂链路、理解机制、设计与表达。

## 本课重点

用户刷新“我的图表”后，前端通过登录用户接口恢复身份；服务器从 Redis 会话取用户 ID，再查数据库并执行权限判断。前端菜单控制帮助展示，后端中间件和资源校验决定请求是否允许。

全栈协作不仅要接口路径一致，还要返回形状、错误语义、字段类型一致。仓库存在生成客户端与 Go 接口的静态契约差异，课程会直接说明，不能照抄“完全对接”作为已验证结果。

## 主链与职责

```text
登录表单 → /user/login → 校验账号密码 → Session 保存 userId
刷新页面 → getInitialState → /user/get/login
         → Cookie → Redis 会话 → Auth 查 user → 脱敏 VO
我的列表 → MyPage 强制 req.UserID=当前用户 → Page 查询
SSE 订阅 → Auth → 查询图表 → 校验归属 → 建流
```

前端全局 initialState 保存当前用户供页面与 canAdmin 使用；后端不信任这个缓存，每次鉴权从会话和数据库恢复身份。普通用户绕过菜单发请求时，仍需通过 Admin 中间件。

## 源码阅读

1. [登录页面](../../frontend/src/pages/User/Login/index.tsx)与[app.tsx](../../frontend/src/app.tsx)的 `getInitialState`、`onPageChange`：获取身份、设置布局、无身份时跳转登录。
2. [requestErrorConfig](../../frontend/src/requestErrorConfig.ts)与 app 的 request：`withCredentials=true`；当前错误抛出器使用 success/errorCode/errorMessage。
3. [UserHandler.Login](../../backend/internal/handler/user_handler.go)：校验成功后 session.Set(user.ID)，Save 成功后返回 LoginUserVO。
4. [SessionStore](../../backend/internal/bootstrap/session.go)：Redis 存储，Cookie 名 GENBI_SESSION，Path=/，HttpOnly，SameSite=Lax，默认过期 30 天。
5. [Auth/Admin](../../backend/internal/middleware/auth.go)：从会话取正整数 int64 ID、查用户、注入请求 Context，再判断 admin 角色。
6. [ChartHandler.MyPage](../../backend/internal/handler/chart_handler.go)、[ChartService.Delete/Edit](../../backend/internal/service/chart_service.go)与 [SSEHandler](../../backend/internal/handler/sse_handler.go)：分别对应列表限定、修改归属、订阅归属。

后端响应的真实形状：

```go
type BaseResponse struct {
    Code int `json:"code"`
    Data any `json:"data"`
    Message string `json:"message"`
}
// Code==0 表示业务成功
```

而前端 errorThrower 解构 `success`，并以 `!success` 抛错。双方没有在这个位置实现统一适配，这是需要联调确认并修正的契约点。

## 机制与边界

后端业务错误通常仍返回 HTTP 200，客户端必须解析 code；不能把 HTTP 2xx 当业务成功。同步返回 BiResponse，异步返回整数 ID，但[生成客户端](../../frontend/src/services/yubi/chartController.ts)把异步方法标为 BaseResponseBiResponse。页面当前只检查 data 是否非空，类型却不能正确描述接口。

当前 Go Router 没有注册前端 openAPI 配置指向的 `/api/v2/api-docs`。因此保留生成配置不证明当前 Go 服务能重新生成客户端，更不能证明所有历史 post/file/queue 客户端都存在对应 Go 路由。

MyPage 会覆盖客户端 userId，Delete/Edit 检查本人或管理员，SSE 仅允许归属者。普通 GetByID 与 Page 路由只有登录门禁，没有统一资源归属限制；登录不等于完整租户隔离。账号注册“先查重复再插入”，SQL 中账号索引不是 UNIQUE，并发注册仍可重复。密码为固定盐 MD5，Cookie 没有 Secure 配置，当前不适合宣称生产级账户安全。

## 需要懂什么

会话把凭据与浏览器可读业务状态分开，HttpOnly 减少脚本读 Cookie 的机会，但不会自动完成 CSRF、XSS、TLS 或权限控制。SameSite=Lax 是一项浏览器策略，仍需按实际部署补齐防护。

类型声明是编译期约束，无法校验服务端真实返回。统一的成功/错误 envelope、同步与异步结果联合类型、接口契约检查应共同维护。错误展示与接口语义应分层：先正确判断 code，再选择 toast 或跳转。

生产演进可以采用密码专用哈希、唯一索引、Secure Cookie、统一图表访问策略及 CSRF 防护；这些在本仓库尚未完整实现。

## 需要记住什么

- 前端身份用于展示；后端会话、角色与归属检查负责授权。
- code/data/message 是 Go 实际契约；success/errorCode/errorMessage 是前端残留契约。
- 异步 data 是 ID；生成类型与 OpenAPI 地址仍需同步。
- 权限检查分散在具体路径，不能说所有图表接口均已隔离。回到[Q7](../GenBI/面经.md#q7-会话与权限)先讲正常链，再讲边界。
