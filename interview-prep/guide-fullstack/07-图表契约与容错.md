# C07 模型返回一段 JSON：图表契约与渲染容错

> 课程性质：核心  
> 返回：[主导学](../GenBI/导学.md)；前置：[C03 模型生成](03-上传与同步生成.md)、[C06 页面更新](06-SSE与轮询.md)；下一课：[C08 列表与预览](08-列表状态与数据预览.md)。  
> 对应：B5；[Q5 图表契约](../GenBI/面经.md#q5-图表契约与渲染容错)；目标掌握：看懂链路、理解机制、设计与表达。

## 本课重点

AI 返回一个 ECharts option 字符串，前端把它当作不可信的运行期数据：先解析 JSON，再执行 Zod 结构检查和过滤，最后交给组件渲染。正常图、解析失败和渲染异常各有不同出口。

当前 schema 校验属于宽松结构检查，sanitize 是启发式过滤，schema 失败时仍尝试渲染过滤后的对象。可以写“结构校验与渲染容错”，不能写“严格拒绝非法配置”或“完全隔离所有注入风险”。

## 主链与职责

```text
rawChartJson → SafeChart.useMemo → parseChartOption
 → JSON.parse（失败再提取首尾花括号）
 → Zod.safeParse
   ├─ 成功 → sanitize → 可选移除 title → ECharts
   └─ 失败 → error + fallbackOption → 警告 + ECharts
ECharts React 子树异常 → ChartErrorBoundary → 错误页 + 重试
```

SafeChart 被同步生成页、我的图表和看板复用，统一原始字符串入口。状态更新只影响输入，解析与展示的职责集中在组件与工具函数。

## 源码阅读

1. [chartSchema](../../frontend/src/utils/chartSchema.ts)中的 EChartsSeriesSchema：限定 type 枚举，data 可选；OptionSchema 要求非空 series，其余大量字段为 any，且 passthrough 保留额外字段。
2. 同文件的 `parseChartOption`：为空返回固定 fallback；解析失败尝试首个 `{` 到最后 `}`；schema 失败返回 error 与过滤后的 parsed 对象。
3. 同文件的 `sanitize`：JSON.stringify replacer 删除含 function 或 `=>` 的字符串，以及危险 key 下的字符串值。
4. [SafeChart](../../frontend/src/components/SafeChart/index.tsx)：useMemo 依赖 rawChartJson、stripTitle；失败时 Alert 提示，然后仍可把 fallbackOption 传给 ReactECharts。
5. [ChartErrorBoundary](../../frontend/src/components/ChartErrorBoundary/index.tsx)：getDerivedStateFromError 保存错误，handleRetry 清除错误并可调用 onRetry；[调用方](../../frontend/src/pages/myChart/index.tsx)当前未传重试回调。
6. 后端[图表清洗](../../backend/internal/util/echarts.go)只做 json.Valid，是另一层较弱的语法容错。

关键分支：

```ts
const result = EChartsOptionSchema.safeParse(parsed);
if (!result.success) {
  return {
    success: false,
    error: `Schema 校验失败：${issues}`,
    fallbackOption:
      typeof parsed === 'object' && parsed !== null
        ? sanitize(parsed as Record<string, any>)
        : FALLBACK_OPTION,
  };
}
```

这里的 fallbackOption 并非永远是固定安全空图。读懂这一段，才不会把“校验失败”误讲成“禁止渲染”。

## 机制与边界

输入合法折线图时，series 至少一项且 type=line，校验通过，过滤后渲染。`stripTitle=true` 用于列表和看板，避免配置标题与卡片标题重复。这个规范化在校验成功分支执行，失败 fallback 分支没有同样处理。

输入纯文本时，提取不到对象，显示警告并渲染固定空柱状图。输入 `{}` 时，JSON 语法正确、schema 因没有 series 失败，fallback 是过滤后的 `{}`，ECharts 的结果与异常由后续组件决定。后端 succeed 也不自动意味着可视化已通过结构检查。

过滤会删除任何含 function/箭头文本的字符串，可能误删普通文案；危险 key 的对象值、其他允许字段及更复杂输入并没有严格白名单。JSON.parse 不执行 JS，不存在此路径中的 eval，但这不能直接推出所有 ECharts 富文本、链接、资源或资源耗尽风险都消失。还没有尺寸、深度或 series 数据量上限。

Error Boundary 捕获其 React 子树渲染、生命周期等错误，不处理外部异步回调和事件处理器的所有异常。边界也不会因 rawChartJson 改变自动清除 hasError，需显式重试或重新挂载。当前未传 onRetry 时，按钮只是重置边界并用原输入再次渲染。

## 需要懂什么

TypeScript 类型只约束编译期，模型返回的字符串必须在运行期解析。Zod 让输入是否符合所定义的 schema 可观察，但 schema 本身的宽松程度决定保证范围，不能把使用库名当作安全结论。

容错与安全取舍要分别处理：宽松 fallback 尽量保留可显示内容，但仍扩大接受输入范围。若安全要求更高，可对失败配置仅显示固定空图，使用字段白名单与数据预算，服务端也在落库前做结构校验。这是未来改进，当前行为仍是警告后尝试 fallback。

组件复用让入口一致；useMemo 减少同输入的重复解析，不意味着大型图表一定流畅。渲染规模仍取决于实际 option 数据与 ECharts 工作量。

## 需要记住什么

- 原始字符串 → JSON → schema → sanitize → 渲染边界，各层保证不同。
- series 非空、type 枚举；其他字段宽松且 passthrough。
- schema 失败仍可尝试过滤对象；重试按钮不一定重新请求。
