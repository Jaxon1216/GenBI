# C09 把多张图组合起来：看板布局与本地快照

> 课程性质：核心  
> 返回：[主导学](../GenBI/导学.md)；前置：[C07 图表组件](07-图表契约与容错.md)、[C08 列表](08-列表状态与数据预览.md)；下一课：[C10 工程交付](10-测试与交付边界.md)。  
> 对应：B6；[Q6 看板与预览](../GenBI/面经.md#q6-看板与数据预览)；目标掌握：看懂链路、理解机制、设计与表达。

## 本课重点

用户把已成功生成的图表加入看板，拖拽、缩放卡片，再点击保存布局。图表来自服务端个人列表，看板保存的是浏览器中的图表对象快照和布局；当前没有看板数据库接口或跨设备同步。

图表 ID 同时用于业务去重、React key 与布局 item key，连接“哪一张图”和“哪一个格子”。位置状态与图表内容必须分别维护。

## 主链与职责

```text
挂载 → localStorage → items/layouts
添加弹窗 → 每页20条循环查询我的图表 → 筛选 succeed
 → selectedChartIds → 排除已存在ID → items
拖拽/缩放 → onLayoutChange → layouts
保存 → JSON.stringify({items,layouts}) → localStorage
刷新 → loadDashboard → 恢复快照 → SafeChart
```

默认布局按两列安排：lg 断点 12 栅格，每项宽 6、高 4；已有 lg 布局按字符串 chartId 查找并复用。ResponsiveGridLayout 根据容器宽度处理断点，WidthProvider 提供宽度。

## 源码阅读

1. [Dashboard](../../frontend/src/pages/Dashboard/index.tsx)的 DashboardItem/State：items 里同时包含 chartId 与整个 API.Chart；layouts 是按断点组织的布局。
2. `loadDashboard/saveDashboard`：统一 key 为 genbi_dashboard；读取 JSON 失败回空，保存没有 try/catch。
3. `openAddModal`：从第 1 页开始 pageSize=20，records.length===20 时继续；全部读完后只显示 succeed。
4. `handleAddCharts`：Set 排除已加入的 ID，已存在选项 disabled；用函数式 setItems 追加。
5. `generateDefaultLayout/handleLayoutChange`：复用 lg 原位置、生成缺失位置；组件实际只传入 `layouts={{lg:...}}`。
6. SafeChart 接受保存的 genChart，并 `stripTitle`，与生成页、个人列表共用[C07](07-图表契约与容错.md)的入口。

绑定布局与图表：

```ts
const existingLayout = layouts.lg?.find((l) => l.i === String(item.chartId));
if (existingLayout) return existingLayout;
return {
  i: String(item.chartId), x: (index % 2) * 6,
  y: Math.floor(index / 2) * 4, w: 6, h: 4, minW: 3, minH: 3,
};
```

布局索引不使用数组序号作身份，因此删除一张图后剩余图仍可按 ID 找回原位置。初始布局的 index 只决定新项位置。

## 机制与边界

布局变化先进入 React state，需要手动点击保存才落本地；刷新会恢复最近保存快照。删除只移除 items，layouts 中旧项可能残留，渲染时按现存 items 生成 lg 布局。重置确认后清空 state 与 key。

本地 key 没有用户 ID，共用浏览器换账号仍可能读到旧看板；存储对象含图表与 CSV 快照，没有 schema、版本和归属检查。服务端图表更新或删除后，保存对象也不会自动重取，因此不能承诺显示最新内容或安全的多账号隔离。

虽然 onLayoutChange 保存 allLayouts，渲染只传 lg，所以不能说已经完整恢复各个断点的人工布局。读取只处理语法异常，合法但结构错误的 JSON 仍可能在渲染时出错；localStorage 配额与禁用导致的写入异常也没有用户反馈。

添加弹窗串行扫描全部分页，没有取消、页数上限或数据变化快照。最后一页恰好 20 条时还会请求一个空页，这是当前循环的自然结果；不断新增时也可能延长扫描。数据量大时应改服务端过滤、分页选择或搜索。

## 需要懂什么

保存位置是 UI 偏好，保存图表对象是数据快照。两者生命周期不同：布局可以长期保留，而业务内容应按 ID 重新读取并重新鉴权。将 chartId、布局和缓存分开后，才能讨论最新性、容量与跨设备同步。

稳定 key 让 React 与栅格组件跟踪同一个对象，但不能代替去重检查，也不会自动清理陈旧布局。断点恢复要将完整 layouts 按实际组件契约传回，不能只在 storage 中存在就视为功能完成。

未来可用按用户隔离、有版本校验的本地偏好，或后端保存看板 ID/图表 ID/布局；运行时拉取有权限的最新图表。并发编辑、分享与版本冲突属于再下一步，当前未实现。

## 需要记住什么

- 只选择 succeed 图表，chartId 贯穿业务、React 与布局身份。
- 手动保存 items+layouts，本地完整图表快照；没有跨设备同步。
- 当前只传 lg 布局、存储 key 未分用户、图表快照不会自动更新。
