# C03 上传一份表格：同步生成与模型契约

> 课程性质：核心  
> 返回：[主导学](../GenBI/导学.md)；前置：[C02 接口契约](02-会话与接口契约.md)；下一课：[C04 事务消息表](04-事务消息表.md)。  
> 对应：B1；[Q1 分析编排](../GenBI/面经.md#q1-同步与异步分析编排)；目标掌握：看懂链路、理解机制、设计与表达。

## 本课重点

用户提交“分析访问量增长”、折线图与表格文件，同步路径转换数据、调用 DeepSeek、保存结果，再把图表配置和结论返回页面。异步路径复用相同的参数解析、CSV 与 prompt 规则，差别在于任务何时执行和结果何时交付。

模型提示词要求输出 JSON，但实际代码仍需解析与容错。提示词、JSON 语法有效、图表结构有效、结论正确是四个不同层次。

## 主链与职责

```text
Form values → originFileObj → FormData(file) + query(name/goal/chartType)
 → Auth → parseGenRequest → ExcelToCSV → 每用户限流
 → GenSync → BuildPrompt → AnalyzeCsv → CleanEchartsJSON
 → MySQL chart(succeed) → BiResponse → 页面 SafeChart
```

前端 submitting 禁用按钮，减少同一页面连续提交；服务端 Redis 按 `gen_chart:用户ID` 控制每秒 3 次的速率，同步与异步共用 key。它限制调用频率，不是文件大小控制，也不是全局任务并发上限。

## 源码阅读

1. [AddChart.onFinish](../../frontend/src/pages/AddChart/index.tsx)：提交开始清除旧结果，获取 `values.file.file.originFileObj`，调用客户端，再保存 chart/rawChartJson。
2. [chartController](../../frontend/src/services/yubi/chartController.ts)的 `genChartByAiUsingPost`：文件在 FormData 中，业务参数在 query 中，没有手写 multipart boundary。
3. [parseGenRequest](../../backend/internal/handler/chart_handler.go)：支持 form/query，要求 name、goal、chartType、file；[ExcelToCSV](../../backend/internal/util/excel.go)识别后缀，只读 xlsx 第一个 sheet，CSV 原样读取。
4. [Limiter.Allow](../../backend/internal/ratelimit/limiter.go)：`redis_rate.PerSecond(3)`，Redis 调用 Context 上限 2 秒。
5. [GenSync/BuildPrompt](../../backend/internal/service/chart_service.go)：将目标、类型、CSV 组成输入；生成成功、清洗后插入数据库，失败则返回错误。
6. [AnalyzeCsv](../../backend/internal/service/deepseek_service.go)：HTTP client 60 秒，使用 NewRequestWithContext，模型 deepseek-chat、temperature 0.1、max_tokens 1024；解两层 JSON 并把结论归一成字符串。
7. [CleanEchartsJSON](../../backend/internal/util/echarts.go)，接[C07](07-图表契约与容错.md)的前端结构校验。

CSV 的关键转义：

```go
if strings.ContainsAny(value, ",\"\n\r") {
    return "\"" + strings.ReplaceAll(value, "\"", "\"\"") + "\""
}
```

包含逗号的一个单元格仍应表示一个字段，引号本身要双写；简单拼逗号会改变列数。这个实现与前端预览的简单 split 不一致，见 C08。

## 机制与边界

后端参数全必填，而前端目前仅 goal 配置 required，文件原对象缺失可能在请求前抛错。Upload 没有 beforeUpload 的拦截配置，表单选文件与最终业务上传需要分别审视；不能描述成完整受控文件选择流程。

解析文件发生在限流之前。当前按后缀判断类型、整文件读取，没有请求体上限、行数限制或模型输入预算。xlsx 空白行被跳过、只读首 sheet；CSV 原样透传，没有统一编码与内容验证。因此该路径支持表格上传，不代表任意大小、编码或恶意输入都已处理。

AnalyzeCsv 先解 API 的 choices，再解 content 内的 genChart/genResult；未检查 HTTP 状态码，也没有重试、熔断或流式 token 处理。system prompt 的“只基于数据”是要求，不能保证模型不幻觉。CleanEchartsJSON 只保证 json.Valid，非法回退 `{}`；GenSync 仍可能把这个值以 succeed 保存，后续图表结构校验才发现没有 series。

同步 Context 来自 HTTP 请求，没有单独套用 consumer 的 30 秒任务预算；它受请求取消与 client 的 60 秒限制。AI 生成成功但数据库写入失败时，调用成本已经发生，结果不会以成功响应返回。请求的 UI 防重复也没有服务端业务幂等键。

## 需要懂什么

表格上传、模型输入、模型输出、可视化是不同契约。只有在每个边界讲清数据形状，才能追踪“上传成功但图不出来”。JSON 合法只是语法层；ECharts schema 与业务结论检查各需自己的机制。

客户端超时必须沿 Context 到真正的网络请求，才能停止等待；只在外层选超时分支可能留下后台执行。浏览器取消等待也不等于上游模型服务已经停止计算。

对于更大数据量，采样、统计聚合、流式读取和输入 token 预算是可选演进；当前并未实现，不能把异步模式包装成大数据分析引擎。

## 需要记住什么

- 文件在 multipart body，name/goal/chartType 可走 query；后端全必填。
- xlsx 首 sheet → CSV；csv 原样；限流在解析之后，同步异步共用用户 key。
- 模型两层 JSON、60 秒客户端；非法图表 JSON 清洗回退 `{}`，不等于图表可渲染。
- 同步生成后保存再返回；异步先受理再执行。用[Q1](../GenBI/面经.md#q1-同步与异步分析编排)串起两条链。
