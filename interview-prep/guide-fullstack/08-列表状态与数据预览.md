# C08 搜索和查看原始数据：列表状态与虚拟化

> 课程性质：核心  
> 返回：[主导学](../GenBI/导学.md)；前置：[C06 更新通道](06-SSE与轮询.md)、[C07 渲染](07-图表契约与容错.md)；下一课：[C09 看板](09-看板布局与持久化.md)。  
> 对应：B4、B6；[Q4](../GenBI/面经.md#q4-sse-与轮询)、[Q6 看板与预览](../GenBI/面经.md#q6-看板与数据预览)；目标掌握：看懂链路、理解机制、设计与表达。

## 本课重点

用户在第二页搜索图表名称，搜索把页码重置为 1；服务端强制当前用户条件，返回 records 和 total。页面按任务状态渲染不同卡片，只有成功图表提供原始 CSV 弹窗。

图表列表采用服务端分页；CSV 弹窗采用 react-window 虚拟行。这两个机制解决不同规模问题：一个限制传回多少图表，一个限制创建多少行 DOM。

## 主链与职责

```text
搜索/翻页 → searchParams → effect.loadData
 → /chart/my/list/page → 强制用户条件 → Count + Limit/Offset → records,total
 → chartList → 状态卡片 + pending ID → SSE/轮询
点击“查看原始数据” → dataModalChart → parseCsv → FixedSizeList → 可见行
```

searchParams 是查询身份；chartList 是最近接受的服务器结果；dataModalChart 是用户选中的预览对象。loading 控制首次骨架与普通加载，静默更新避免反复出现大加载态。

## 源码阅读

1. [MyChartPage](../../frontend/src/pages/myChart/index.tsx)：默认 current=1、pageSize=4；搜索基于 initSearchParams 重置；分页基于现有条件修改。
2. 同文件的 loadData、pollCallback、pendingChartIds：loadData 更新列表与总数；事件和轮询复用它；pending 只来自当前页。
3. [MyPage](../../backend/internal/handler/chart_handler.go)：覆盖 req.UserID。[ChartService.Page](../../backend/internal/service/chart_service.go)：页大小上限 20，Count 后 Offset/Limit，默认 createTime DESC。
4. [图表 SQL](../../backend/sql/create_table.sql)：按 userId 建索引，没有本场景的复合时间/ID 索引。
5. [VirtualDataTable](../../frontend/src/components/VirtualDataTable/index.tsx)：parseCsv、ROW_HEIGHT=40、MAX_VISIBLE_ROWS=15，useMemo 解析，FixedSizeList 按 index 读取行。

虚拟列表参数：

```tsx
const listHeight = Math.min(rows.length, MAX_VISIBLE_ROWS) * ROW_HEIGHT;
<VirtualList height={listHeight || ROW_HEIGHT}
  itemCount={rows.length} itemSize={ROW_HEIGHT} width="100%">
  {renderRow}
</VirtualList>
```

高度是最多 15 个行高，实际 DOM 还会包含库的 overscan；不能说“任何时候严格只有 15 行”。全部 rows 仍在内存里，parseCsv 仍遍历整段字符串。

## 机制与边界

普通周期轮询等待 loadData 完成后再安排下一次，但搜索、新分页、SSE 和可见性刷新仍可相互重叠。当前 loadData 没有取消或请求序号检查：旧搜索 A 慢返回、新搜索 B 快返回，A 仍可能覆盖 B。useCallback 固定依赖只是函数身份管理，不负责接受响应的时序。

更可靠的方案是在每次查询递增序号、只接受当前查询响应，或用 AbortController 取消过期请求，并在提交状态处再次核验查询身份。这个保护尚未实现，简历不要写成“已消除搜索竞态”。

分页默认只按 createTime 排序，同时间数据没有 ID 作为稳定第二排序，新增记录也会改变 offset 边界。Count 和查询不是单个快照事务，因此总数与列表可能来自不同时间。深分页会扫描更多数据，可考虑 `(userId, createTime, id)` 复合索引与游标，但要结合真实查询计划决定。

前端 CSV 预览直接 split 换行和逗号，不支持引号字段、嵌入换行、引号转义；例如 `"华东,上海",10` 会错分成多列，而后端 xlsx 导出合法 CSV 会保留这一单元格。虚拟化不会修正解析错误。弹窗按列数计算宽度，没有完善移动端宽表约束或表格语义，不能宣称复杂 CSV 与移动端都已兼容。

## 需要懂什么

查询状态与展示状态要绑定：不仅知道“请求发出时用了什么参数”，还要在返回时判断“当前是否还需要这个响应”。推送和定时器越多，越需要统一接受规则。

分页降低响应条目规模，虚拟化降低渲染节点规模，二者不减少每个图表的 CSV 存储或返回字节数。即使只返回四个图表，每项仍带完整 chartData，网络负载可能很大。

正确 CSV 解析与 DOM 性能独立。可用符合 CSV 语义的解析器，或让服务端以分页行数据提供预览；对于大文件，后者还可以控制传输和内存预算。

## 需要记住什么

- 默认每页 4 条，服务端最大 20；搜索重置页码，MyPage 覆盖 userId。
- state 快照只比 ID/状态；查询没有过期响应保护，排序没有 ID 兜底。
- react-window 是渲染窗口，完整 CSV 仍被解析；40px 行高，15 行视口，另有 overscan。
- 简单 split 不支持标准带引号 CSV。回到[Q6](../GenBI/面经.md#q6-看板与数据预览)分清“规模优化”与“数据正确性”。
