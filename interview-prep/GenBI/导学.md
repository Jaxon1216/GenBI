## 学习目标与项目地图

GenBI 帮助用户把上传的表格转换为图表与分析结论，再将多图组合进看板。项目的主要工程问题是跨层数据契约、长时间生成的受理与结果交付、数据库与消息投递协作，以及浏览器接收异步状态。这里依据现有实现组织学习，没有补造线上规模或历史业务目标。

岗位定位适合 **React/TypeScript + Go 的全栈开发、企业中后台、数据可视化和 AI 应用开发**。求职时重点讲前后端如何协作完成任务，而不仅是调用模型。仓库不包含检索增强、Agent 工具编排、模型训练或 Kubernetes，不把这些作为已有经历。没有具体 JD 时，这是项目能力定位，不代表某家公司当前在招或已经满足资深岗位要求。

| 模块 | 真实职责 | 主要入口 |
| --- | --- | --- |
| React 18 / Umi Max 4 / TypeScript 5.9.3 | 表单、身份展示、列表状态、图表渲染、看板布局 | [routes.ts](../../frontend/config/routes.ts)、[app.tsx](../../frontend/src/app.tsx) |
| Gin HTTP server | 会话鉴权、上传受理、同步生成、列表查询、SSE 转发 | [server/main.go](../../backend/cmd/server/main.go)、[router.go](../../backend/internal/bootstrap/router.go) |
| ChartService / DeepSeekService | 保存业务输入、状态抢占、调用模型、保存结果 | [chart_service.go](../../backend/internal/service/chart_service.go)、[deepseek_service.go](../../backend/internal/service/deepseek_service.go) |
| MySQL / GORM | 用户、图表任务与事务消息表 | [建表 SQL](../../backend/sql/create_table.sql)、[outbox SQL](../../backend/sql/02_outbox.sql) |
| RabbitMQ / outbox relay / consumer | 投递待生成 ID、领取与后台执行 | [relay.go](../../backend/internal/outbox/relay.go)、[consumer/main.go](../../backend/cmd/consumer/main.go) |
| Redis | server 会话与限流；consumer/server 之间的事件转发 | [session.go](../../backend/internal/bootstrap/session.go)、[redis_publisher.go](../../backend/internal/event/redis_publisher.go) |

四条代表性链路：

```text
1. 登录 → Redis 会话 → 刷新恢复身份 → Auth → 我的图表查询
2. 同步上传 → 表格转 CSV → 模型 HTTP → 清洗 → chart(succeed) → SafeChart
3. 异步上传 → chart(wait)+outbox(pending)事务 → relay → MQ
             → consumer CAS(running) → 模型 → chart(succeed)
             → Redis通知 → SSE → 前端重新查列表
4. 选择成功图表 → 看板去重/布局 → localStorage手动保存 → 刷新恢复快照
```

理解状态归属：任务事实在 MySQL，通知在 Redis/SSE，页面展示在 React，布局快照在 localStorage。通知可能丢失，缓存可能陈旧，页面加载成功不等于任务成功。

## 学习重点与记忆提纲

先理解四个因果：为什么 chart 与 outbox 必须同事务；为什么 wait 条件 UPDATE 能仲裁却会阻止当前重试；为什么通知不能替代数据库事实；为什么 JSON 合法还需要结构检查。对应 [C04](../guide-fullstack/04-事务消息表.md)～[C07](../guide-fullstack/07-图表契约与容错.md)。

再记住四条主链：登录恢复、同步生成、异步受理到显示、看板保存恢复。最后用[面经 Q1～Q8](面经.md#面试问题)组织第一人称口播：先回答问题，再讲机制、具体例子和边界。源码路径是定位工具，无需在回答中逐个背文件名。

参数只在解释机制时使用：用户速率每秒 3 次；relay 默认 5 秒/100 条；consumer prefetch=1、任务 Context 30 秒、最多两次处理调用；模型 HTTP client 60 秒；SSE 心跳 15 秒/建连超时 10 秒；轮询 3～30 秒。这些不是实测吞吐或耗时成绩。
